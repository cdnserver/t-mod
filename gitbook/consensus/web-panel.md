# Веб-панель консенсуса

T-Mod поднимает отдельную read-only панель для администратора. Производственный доступ работает
через Cloudflare Tunnel по адресу:

```text
https://tmod.rundans.lat
```

Панель показывает:

* текущий этап и ведущего заседания;
* кворум и подтверждение участников;
* таймер и количество полученных голосов;
* состояние четырёх блоков после фиксации результата;
* текущий законопроект и ссылку на оригинал;
* очередь следующих проектов и последние решения.

Если из `#тест-бота` запущен учебный консенсус, сверху появляется переключатель
**«Рабочий / Симуляция»**. Симуляция обновляется с той же частотой и позволяет проверить весь
интерфейс панели. Рабочая очередь, реальные результаты и учебные данные при этом не смешиваются.

Во время активного голосования направления индивидуальных голосов не раскрываются. Администратор
видит только факт получения голоса. Это позволяет следить за техническим ходом заседания, не
влияя на ещё не завершившееся решение.

## Домен и локальный origin

Cloudflare принимает внешний HTTPS-трафик, а служба `cloudflared` передаёт его локальному origin:

```text
http://127.0.0.1:8787
```

Docker привязывает порт только к `127.0.0.1`. Поэтому к origin нельзя подключиться напрямую из
LAN, WireGuard или интернета. Открывать порт на роутере не нужно.

## Автоматическая настройка Windows

Обычный запуск через файл **`Start T-Mod.bat` на рабочем столе** выполняет всю серверную настройку
сам:

1. включает панель и записывает `https://tmod.rundans.lat` в постоянный `.env`;
2. запускает Docker Desktop, если он ещё не запущен;
3. находит путь к рабочему `config.yml` службы `cloudflared`;
4. создаёт резервную копию конфига;
5. добавляет маршрут `tmod.rundans.lat → http://127.0.0.1:8787` первым правилом `ingress`;
6. проверяет конфиг штатной командой `cloudflared tunnel ingress validate`;
7. при ошибке возвращает исходный конфиг, а при успехе перезапускает службу;
8. пересобирает контейнер и ждёт успешного ответа `/api/health`.

При первом запуске Windows один раз запросит права администратора. Подтвердите этот запрос.
Повторные запуски не требуют повышения прав, пока маршрут и служба остаются исправны.

Остальные маршруты существующего туннеля сохраняются без изменений.

## Домен через Cloudflare Tunnel

Лаунчер автоматически добавляет в существующий локальный конфиг маршрут:

```text
Hostname: tmod.rundans.lat
Service URL: http://127.0.0.1:8787
```

После проверки лаунчер пытается создать DNS-маршрут через `cloudflared tunnel route dns`. Если
локального сертификата Cloudflare недостаточно, он выдаст предупреждение: тогда в панели
Cloudflare нужно один раз добавить Published application с теми же hostname и Service URL.
Другие сайты этого туннеля останутся без изменений.

```text
CONSENSUS_WEB_PUBLIC_URL=https://tmod.rundans.lat
```

Кнопка **«Веб-панель»** в Discord показывает доменный адрес без порта. Настройте для hostname
приложение Cloudflare Access и разрешите вход только администраторам. Собственный ключ T-Mod
остаётся вторым уровнем защиты.

{% hint style="warning" %}
Не создавайте обычное перенаправление TCP-порта `8787` на роутере. Cloudflare Tunnel устанавливает
исходящее соединение и не требует открытого входящего порта.
{% endhint %}

## Вход

Панель защищена отдельным ключом. Администратор получает адрес и ключ в Discord:

1. откройте канал **«Настройки бота»**;
2. нажмите **«Веб-панель»**;
3. скопируйте скрытый ключ;
4. вставьте его на странице входа.

Если `CONSENSUS_WEB_TOKEN` не задан, T-Mod один раз создаёт сильный ключ и сохраняет его в
постоянной базе. Перезапуск контейнера ключ не меняет. Браузер хранит его только до закрытия
вкладки.

{% hint style="warning" %}
Не публикуйте ключ доступа. Не создавайте перенаправление порта `8787`: снаружи должен быть
доступен только HTTPS-домен Cloudflare.
{% endhint %}

## Запуск после обновления

Откройте на рабочем столе:

```text
Start T-Mod.bat
```

Лаунчер сам обновит проект, настроит сеть, пересоберёт контейнер и проверит панель. Ручная команда
`docker compose up` для штатного обновления больше не нужна.

## Если страница не открывается

Проверьте по порядку:

1. контейнер пересобран, а не только перезапущен;
2. в `docker-compose.yml` присутствует `127.0.0.1:8787:8787`;
3. `CONSENSUS_WEB_ENABLED=true`;
4. на сервере отвечает `http://127.0.0.1:8787/api/health`;
5. служба `cloudflared` находится в состоянии Running;
6. в её `config.yml` присутствует маршрут `tmod.rundans.lat`;
7. hostname существует в DNS Cloudflare.

Если origin отвечает, а домен показывает ошибку `502`, проблема находится между службой
`cloudflared` и её маршрутом. Если домен не разрешается, нужно создать Published application или
DNS-маршрут в Cloudflare.
