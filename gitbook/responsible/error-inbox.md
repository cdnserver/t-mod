# Автоматический Error Inbox

T-Mod умеет сохранять runtime-ошибки в локальную очередь и публиковать их как закрытые GitHub
Issues репозитория `cdnserver/t-mod`. Бот **не коммитит логи в `main`** и не получает право менять
код: это исключает конфликты при обновлении и случайное попадание трассировок в историю Git.

## Как это работает

1. Ошибка сразу записывается в SQLite, даже если интернет или GitHub недоступны.
2. Из текста удаляются известные токены, пароли, API-ключи, Discord webhook и приватные ключи.
3. Одинаковые ошибки объединяются по fingerprint, а счётчик повторов увеличивается.
4. Фоновый worker создаёт Issue в приватном репозитории.
5. Если закрытая ошибка повторилась, Issue автоматически открывается снова и получает новый
   комментарий. Комментарии ограничены cooldown, поэтому GitHub не превращается в поток дублей.
6. При ошибке доставки используется экспоненциальная задержка. Работа Discord, веба и Minecraft от
   GitHub не зависит.

Отчёт содержит компонент, тип исключения, версию запуска, первый и последний случай, количество
повторов, безопасный контекст и traceback.

## Однократная настройка GitHub

Создайте fine-grained personal access token для приватного репозитория `cdnserver/t-mod`:

- доступ только к выбранному репозиторию `t-mod`;
- Repository permissions → **Issues: Read and write**;
- Contents, Actions, Administration и остальные права не нужны.

В файл `C:\Users\Admin\Documents\SGLDiscordBot\.env` добавьте или измените:

```dotenv
ERROR_INBOX_CAPTURE_ENABLED=true
ERROR_INBOX_PUBLISH_ENABLED=true
ERROR_INBOX_GITHUB_REPOSITORY=cdnserver/t-mod
ERROR_INBOX_GITHUB_TOKEN=ВСТАВЬТЕ_FINE_GRAINED_TOKEN
ERROR_INBOX_GITHUB_LABEL=tmod-runtime
```

Не отправляйте этот токен в Discord и не добавляйте `.env` в Git. После изменения перезапустите
T-Mod обычным батником. В старте должно появиться:

```text
Error Inbox: GitHub publisher ready; repository=cdnserver/t-mod
```

Если метка `tmod-runtime` ещё не создана, первая публикация автоматически повторится без метки и
всё равно сохранит Issue.

## Как получить список ошибок перед исправлением

На компьютере разработчика авторизуйте GitHub CLI командой `gh auth login`, затем выполните:

```bash
python scripts/fetch_runtime_errors.py --output data/runtime-error-inbox.md
```

Файл `data/runtime-error-inbox.md` содержит все открытые отчёты и игнорируется Git. Его можно
передать Codex вместе с командой «исправь ошибки из Error Inbox». Сам `git pull` получает код, а
эта команда получает Issues: Git намеренно не смешивает runtime-данные с веткой `main`.

## Аварийные режимы

- `local spool only` при запуске — сбор работает, но отсутствует токен или публикация выключена.
- HTTP 401/403 — проверьте срок токена и право Issues.
- HTTP 404 — проверьте имя и доступ к приватному репозиторию.
- Удалённый вручную Issue не блокирует очередь: при следующем повторе бот создаст новый.
- Старые успешно опубликованные записи удаляются из локальной базы через 90 дней; ожидающие
  доставки записи не удаляются.
