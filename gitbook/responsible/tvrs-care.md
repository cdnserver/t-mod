# tvrs care

Этот раздел предназначен для председателей и администраторов, которые исправляют редкие ошибки.

{% hint style="danger" %}
Сначала используйте обычный аудит и `/undo`. Ручное редактирование и удаление нужны только тогда, когда безопасная отмена не подходит.
{% endhint %}

## Правильный порядок исправления

1. Откройте `/tvrs` → **«Аудит»**.
2. Найдите действие и его ID.
3. Попробуйте отменить его с понятной причиной.
4. Если бот сообщает о зависимой записи, отменяйте цепочку с самого позднего действия.
5. Только после этого используйте служебные команды TVRS.

## Исправление номера следующего проекта

```
/tvrs_setbill last_accepted:10
```

После этого следующий проект получит номер `011`.

Используйте команду только после проверки существующей очереди. Номер не должен пересекаться с уже созданными проектами.

## Восстановление карточки подачи

Команда `/tvrs_sticky` нужна, если карточку **«Создать законопроект»** удалили или она устарела.

Во время активного консенсуса отсутствие карточки нормально — бот временно закрывает подачу новых проектов и вернёт её после завершения.

## Просмотр проекта перед изменением

```
/tvrs_admin target:bill action:view identifier:011
```

Сначала проверьте номер, заголовок, статус и внутренний ID. Не редактируйте проект только по памяти или скриншоту.

## Исправление текста или статуса

```
/tvrs_admin target:bill action:edit identifier:011 field:title value:Исправленный заголовок
/tvrs_admin target:bill action:edit identifier:011 field:status value:draft
```

Можно исправлять заголовок, суть, материалы, статус и краткий итог.

{% hint style="warning" %}
Изменение сохранённой записи не переписывает старую карточку в Discord. После исправления сообщите участникам, какая версия считается актуальной.
{% endhint %}

## Удаление

Удаление требует явного подтверждения:

```
/tvrs_admin target:bill action:delete identifier:011 confirm:DELETE
```

Отдельно можно удалить ошибочный результат или результаты конкретного пленарного заседания. Это не откатывает автоматически статусы проектов и опубликованные сообщения.

Перед удалением:

* □ Выполнен view
* □ Проверен номер/ID
* □ Понятно, какие связанные данные исчезнут
* □ Есть согласование ответственного лица
* □ Указана причина в рабочем журнале

## Перезапуск во время консенсуса

Активная сессия восстанавливается из базы вместе с этапом, голосами, таймером и идентификаторами
личных сообщений. После запуска проверьте `#лог-тех`, затем откройте `/tvrs` → **«Консенсус»** →
**«Открыть заседание»**.

Не создавайте новую сессию вручную. Если бот остановился непосредственно во время фиксации
результата или вето, он безопасно продолжит эту же операцию при запуске.

Если сохранённая сессия повреждена и не читается, T-Mod изолирует её, вернёт текущий проект в
очередь и отправит объяснение в `#лог-тех`. Такая сессия больше не блокирует запуск нового
заседания.

## После исправления

1. Повторите просмотр записи.
2. Обновите `/tvrs`.
3. Проверьте очередь и карточку подачи.
4. Сообщите участникам о результате исправления.
