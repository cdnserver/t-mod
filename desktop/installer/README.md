# Blackbird Setup — собственный установщик Windows

Локальная реализация, **ещё не включена в релизный канал**. Это нативное окно WPF и собственный механизм установки; NSIS внутри не запускается. Текущий `dist:blackbird` и действующий feed не изменены.

## Что реализовано

- Тёмное окно 900×580: утверждённая птица, подпись Технологий, мягкое проявление сцены и живая орбита. Масштабирование Per-Monitor V2.
- Установка для текущего пользователя без UAC, выбор расположения, ярлык рабочего стола, меню «Пуск», обработчик `blackbird://`, запись в «Установленные приложения» Windows.
- Один self-contained EXE с встроенным ZIP приложения и манифестом SHA-256 каждого файла. Runtime .NET пользователю отдельно устанавливать не нужно; штатное извлечение нативных библиотек .NET во временную папку остаётся.
- Проверенная распаковка в отдельный каталог, журнал с начала распаковки, атомарное переключение каталога приложения, восстановление прежней версии при ошибке, восстановление после прерванного процесса.
- Параллельные установки блокируются. Неизвестная непустая папка не заменяется. Пути с переходами, NTFS ADS, зарезервированные Windows-имена, дубликаты и символические ссылки отклоняются.
- Проверка свободного места; отмена до переключения файлов. Работающий клиент не убивается: предлагается закрыть его через трей.
- Удаление только установленных файлов; профиль аккаунта и `%APPDATA%` не затрагиваются. Собственный журнал позволяет продолжить прерванное удаление; запись Windows сохраняется до очистки файлов. Удаление запускается из собственной временной копии, без автозапуска и фоновых хуков самоуничтожения.
- Поддерживаются аргументы существующего `electron-updater`: `--updated`, `/S`, `--force-run`, `/D=...`. Это совместимость запуска, а не использование NSIS.
- Ошибки сохраняются в `%LOCALAPPDATA%\Blackbird\SetupLogs`.

## Проверки исходников (не выпуск установщика)

Нужен SDK .NET 8. Тесты движка переносимые, реестр и реальный клиент не меняются:

```sh
dotnet run --project desktop/installer/Blackbird.Setup.Tests
```

Проверка компиляции окна может выполняться и не на Windows:

```sh
dotnet build desktop/installer/Blackbird.Setup --no-self-contained -p:PublishSingleFile=false
```

Нативный визуальный предпросмотр — на Windows, без установки и изменения файлов:

```powershell
dotnet run --project desktop/installer/Blackbird.Setup --no-self-contained -p:PublishSingleFile=false -- --preview
```

Без `--preview` исходное окно без встроенного пакета не установит приложение и покажет объяснение. Публикация без пакета запрещена на уровне проекта.

## Выпуск одного EXE — только после отдельного разрешения на сборку

На **Windows x64**, с SDK .NET 8 и рабочим окружением Desktop:

```powershell
cd desktop
pnpm typecheck
pnpm test
pnpm dist:blackbird:custom
```

Команда подготавливает `win-unpacked`, создаёт проверенный архив и публикует собственный EXE в `release-blackbird/custom`. Метаданные называются **`custom-latest.yml`**, а не `latest.yml`: действующий автоапдейт самопроизвольно не переключается. Никакой отправки на GitHub или сервер команда не делает. T-Mod Desktop не изменяется.

## Обязательные gates до переключения production

1. Реальный Windows 10/11 smoke: новый пользователь, кириллица/пробелы в пути, DPI 100/150/200%, установленный и отсутствующий .NET, обычный/отключённый системный motion.
2. Установка → запуск → аккаунт → повторная установка → обновление через текущий `electron-updater` → удаление. Отдельно проверить файлы, реестр, ярлыки, `blackbird://` и сохранность аккаунта.
3. Убийство процесса на распаковке/переключении, занятые файлы, антивирус, нехватка места, два установщика одновременно. Переносимые тесты моделируют часть сбоев, но не заменяют Windows/NTFS-проверку.
4. Миграция старого NSIS-клиента: новая установка использует отдельный каталог `Blackbird Client`. Автоматического удаления старого клиента пока **нет**. Нужно проверить сосуществование, ярлыки, старый деинсталлятор и переход feed; нельзя просто переименовать `custom-latest.yml` в production.
5. Проверить подпись финального EXE и контрольные суммы уже **после** подписания. SHA манифеста проверяет целостность, не заменяет подпись издателя.
6. Проверить поведение восстановления регистрации/ярлыков при аварийном завершении, а не только при пойманном исключении. Журнал файлов не является полной транзакцией реестра Windows.

До закрытия этих gates нельзя объявлять нативный установщик полностью готовым или менять им рабочий канал обновлений.
