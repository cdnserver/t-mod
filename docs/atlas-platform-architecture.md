# Atlas: контуры проектов и выпусков моделей

Atlas рассчитан на несколько игровых проектов и десятки серверов, но не
смешивает их правовые базы. Это правило действует одинаково для загрузок,
форумной синхронизации, поиска, истории диалогов, overlay и подготовки данных
к обучению.

## Структура данных

```text
Atlas platform
├── Общая база правил          — только явно опубликованные общие OOC-материалы
├── Проект                    — например Majestic RP
│   └── Сервер                 — например Phoenix 15
│       └── Фракция            — LSPD, GOV и другие
│           └── Пространство   — частная команда или личный контур
└── Другой проект              — отдельные законы, организации и обучение
```

Каждый источник получает одну каноническую область доступа:

- **Общая база правил** — только для действительно одинаковых для всех
  проектов материалов. Публикуется администратором явным выбором «Всем
  серверам Atlas».
- **Проект** — общие внутри одного проекта документы. Именно так безопасно
  трактуется историческое значение `global` в прежней базе Atlas: старые
  материалы Majestic не становятся доступными новому проекту.
- **Сервер** — законы и правила одного игрового сервера.
- **Фракция** — уставы, регламенты и внутренние памятки конкретной фракции.
- **Пространство** — рабочие заметки и частные материалы одной команды.

Перед выдачей результата Atlas повторно проверяет источник по основной базе.
Поэтому устаревший, перемещённый или случайно оставшийся в векторном индексе
фрагмент не может попасть в чужой ответ. При смене области или проекта источник
ставится на переиндексацию.

Слово `global` в старых формах и API по-прежнему означает **«внутри текущего
проекта»**, а не «для всех клиентов Atlas». Публикация на всю платформу требует
отдельного поля `federation_scope=platform` и явного подтверждения
`confirm_platform_scope=true` в административном действии. Это исключает
случайное раскрытие базы Majestic новому проекту.

## Агенты Atlas

У каждого агента есть самостоятельная роль, область знаний и будущая линия
обучения:

| Агент | Назначение | Линия обучения |
| --- | --- | --- |
| `atlas-tvr-a` | Генеральный помощник | `general` |
| `atlas-claims` | IC-иски и процессуальные документы | `ic-claims` |
| `atlas-complaints` | OOC-жалобы и правила сервера | `ooc-complaints` |
| `atlas-defense` | IC-защита и позиции по делу | `ic-defense` |
| `atlas-documents` | Оформление документов | `documents` |

Специалист получает только подходящие типы источников. Например, агент жалоб
не использует IC-материалы как основание для OOC-ответа. Общая RAG-библиотека
остаётся источником актуальных правил и законов; fine-tuning нужен для манеры
работы, структуры и качества решения задачи, но не заменяет библиотеку.

## Безопасный выпуск модели

1. Собирается отдельный, вручную проверяемый набор для пары
   `проект + агент`.
2. Набор проходит закрытый eval-gate: границы проекта, агента, ссылки на
   источники, запрещённые формулировки и длина ответа.
3. Обученная модель сначала добавляется в выключенный rollout.
4. Canary включается только для выбранной пары `проект + агент`.
5. При временной ошибке нового провайдера Atlas один раз отвечает через
   прежнюю базовую модель. В истории остаётся фактическая модель ответа.

Такая схема позволяет выпускать, например, улучшенный агент исков только для
Majestic RP, не затрагивая ни жалобы, ни другие проекты. Overlay и режим
«Атлас 2» сохраняют собственные быстрые маршруты и не переключаются на
fine-tuned выпуск.

Подробности подготовки набора и eval-gate: [atlas-finetuning.md](atlas-finetuning.md).

## Добавление нового проекта

1. Администратор создаёт проект в каталоге Atlas.
2. Для него создаются серверы с уникальными кодами, затем фракции и рабочие
   пространства.
3. Законы и документы загружаются в нужную область; общие OOC-правила
   публикуются отдельно только при осознанной необходимости.
4. После индексации создаются изолированные eval-кейсы и наборы обучения для
   каждого нужного агента.

У проектов нет «неявной общей папки». Если материал должен быть доступен всем,
это видно в его области доступа и в журнале Atlas.
