# Журнал действий и аудит

Этот раздел нужен, когда в данных появилась ошибка, требуется найти финансовую операцию или понять, кто и когда изменил состояние бота.

Все основные функции можно открыть кнопками через `/tvrs` → **«Аудит»**. Прямые команды ниже
сохранены как быстрые пути для тех, кому удобнее вводить их вручную.

## Три главные команды

| Команда | Для чего |
|---|---|
| `/actions` | Посмотреть свои последние действия и их ID |
| `/undo` | Безопасно отменить последнее или выбранное действие |
| `/finance-audit` | Найти финансовые записи по коду, автору, типу, периоду или причине |

## Журнал `/actions`

Введите:

```text
/actions
```

Бот покажет последние действия, например:

```text
Действие #184 · craft · можно отменить
Продажа по плану #7: 3 шт. за 375000

Действие #183 · craft · можно отменить
Выставлено на маркет по плану #7: 10 шт.
```

Можно оставить только нужный раздел:

```text
/actions module:finance
/actions module:craft
/actions module:sgl
/actions module:tvrs
/actions module:bureau
```

Ответственный за казну или администратор может посмотреть журнал другого участника через параметр `user`.

## Быстрая отмена

Последнее своё действие:

```text
/undo reason:Ошибся при вводе
```

Точная запись:

```text
/undo action_id:184 reason:Неверная сумма продажи
```

Чужое последнее действие, если у вас есть права:

```text
/undo user:@Участник reason:Исправление после проверки
```

Причину лучше указывать всегда. Она остаётся в журнале и объясняет другим участникам, почему данные изменились.

## Правило обратного порядка

Представьте цепочку:

```text
Итог производства → цена → выставление → продажа
```

Нельзя отменить итог, пока действует продажа. Сначала отмените продажу, затем выставление, цену и только потом итог.

Бот сам защищает цепочку и подсказывает ID следующей записи, которую нужно отменить.

## Что происходит с историей

Исходные записи не стираются. Бот помечает действие отменённым и добавляет компенсацию:

- в казне появляется отдельная запись отмены;
- в крафте восстанавливаются предыдущие числа и событие попадает в ветку;
- в делах и голосованиях возвращается предыдущая версия записи;
- в журнале остаются автор отмены, время и причина.

Так проверяющий видит и ошибку, и её исправление.

## Поиск операции по игровому коду

В любом серверном канале выполните:

```text
/finance-audit code:KXRM
```

Сравните результат с операцией в игре:

1. Код должен совпадать полностью.
2. Проверьте сумму.
3. Проверьте автора и время.
4. Прочитайте причину.
5. Посмотрите, не отменена ли запись.
6. Проверьте связь с планом крафта.

Для более широкого расследования комбинируйте фильтры:

```text
/finance-audit user:@Участник days:14
/finance-audit kind:withdraw text:материалы
/finance-audit kind:undo days:30
```

## Статистика для проверки

```text
/finance-stats days:30
/craft-stats days:30
```

Финансовый отчёт помогает увидеть общий поток денег и крупные назначения. Крафтовый — объём производства, расходы, продажи, результат и вклад участников.

Отменённые операции исключаются из итоговых сумм, но остаются доступными в аудите.

## Что `/undo` не делает

Команда не управляет игрой. Она не может физически вернуть деньги, остановить уже поставленный крафт, снять товар с маркета или вернуть проданный предмет.

После исправления проверьте две вещи:

- данные бота снова правильные;
- реальное состояние в игре приведено к тем же значениям.

Если действие имело внешний эффект, который нельзя безопасно отменить автоматически, бот не станет притворяться, что всё исправлено, и сообщит об ограничении.
