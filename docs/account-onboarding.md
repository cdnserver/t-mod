# Создание аккаунта через сайт

Страницы: `/login`, `/register?next=/admission`, `/admission` на домене Phoenix.
Общий стиль и локальные IBM Plex Sans: `web/consensus/blackbird-public.css`.

## Цепочка

1. Браузер запрашивает код. В БД сохраняются только хеши кода и браузерного
   секрета; секрет остаётся в HttpOnly/SameSite=Strict cookie на 15 минут.
2. Участник Discord выполняет `/master code` и подтверждает своё действие
   отдельной кнопкой. Код одноразовый. Бот проверяет членство в домашней гильдии.
3. Страница опрашивает состояние, затем собирает имя обращения, логин,
   пароль (12–128 символов) или PIN (8 цифр) и до трёх персонажей Phoenix.
   Персонажи необязательны для аккаунта, но обязательны для заявки в Сенат.
4. При сохранении сервер снова проверяет членство, блокировку и наличие
   существующего аккаунта. Создание входа и профиля выполняется в одной
   транзакции. Повторный запрос не меняет уже сохранённый пароль.
5. Пользователь входит обычным способом и возвращается к выбранному разделу.

Существующий аккаунт нельзя сбросить через этот мастер. Старые персонажи
сохраняются, новые по умолчанию закрыты. Пустой/нулевой уровень не мешает входу.
Пароли, коды и браузерные секреты не записываются в глобальные HTTP-логи.
Код нельзя подтверждать по просьбе другого человека: он связывает аккаунт
с тем браузером, который его получил.

## Включение на сервере

Нужен обычный `storage.init_db()` при старте для новой таблицы
`account_registrations`, обновление web-ассетов и синхронизация slash-команд
бота. Гильдия `/master` берётся из `CONSENSUS_WEB_GUILD_ID`, затем используется
обычный механизм выбора гильдии `/account`. Она должна совпадать с веб-сервисом.
Для проверки членства боту нужен доступ к участникам сервера. Новые сторонние
API-ключи не требуются.

Проверка локально: `python -m unittest tests.test_account_registration`.
Визуальный стенд: `python scripts/preview_account_onboarding.py` →
`http://127.0.0.1:5183/admission`. `/__lab` явно имитирует Discord только для
вымышленного участника 501. Стенд использует временную SQLite-БД, слушает только
loopback и не включён в production. Это не проверка живого Discord/PostgreSQL.
