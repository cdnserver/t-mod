# Операционный центр TVRS

Операционный центр отделяет запуск действий, текущую работу и историю. Пользователю не нужно
запоминать, в каком канале разрешена команда: `/tvrs`, `/finance`, `/craft`, `/actions`, `/undo`
и команды статистики можно вызывать в любом серверном канале.

## Структура

| Канал | Назначение |
|---|---|
| `панель-управления` | Постоянное общее меню `/tvrs`; ответы кнопок видит только нажавший |
| `активные-задачи` | Одна живая сводка незавершённых дел Товарищества со ссылками на источники |
| `мастерская` | Рецепты, карточки планов, напоминания, ветки и результаты крафтов |
| `лог-финансы` | Вечерняя сверка и хронология финансовых событий |
| `лог-тех` | Состояние T-Mod, новые срезы Majestic и технические ошибки |
| `отчёты` | Каркас будущих ежедневных и недельных сводок |
| `настройки-бота` | Диагностика и восстановление панелей администраторами |
| `тест-бота` | Безопасная проверка доступности без изменения рабочих данных |

## Главное правило

`активные-задачи` не хранит копии карточек. Например, карточка крафта остаётся в мастерской, а
сводка показывает название, состояние, ответственного и прямую ссылку на эту карточку. После
завершения процесса строка автоматически исчезает из сводки, но профильная история сохраняется.

В центр входят только дела Товарищества:

- вечерняя сверка казны, пока она не заполнена;
- активные планы крафта;
- текущий пленарный консенсус;
- очередь законопроектов.

Кейсы SGL, AI-аудио и AI-изображения сюда не попадают.

## Публичная панель и приватность

Сообщение в `панель-управления` видят все. Кнопки **«Казна»**, **«Крафты»**, **«Рынок»**, **«Аудит»**,
**«Консенсус»**, **«Законопроекты»**, **«Справка»**, **«Ссылки»** и **«Обновить»** отвечают
приватно. Чужой пользователь не видит открытое меню и не может управлять им.

Ролевые ограничения сохраняются: например, пленарную панель может открыть только председатель.
Публичные карточки и результаты всегда отправляются в штатный профильный канал, а не туда, где
была нажата кнопка.

## Автоматическая подготовка каналов

При запуске T-Mod проверяет категорию `OPERATIONS_CATEGORY_ID`. Канал с известным ID используется
сразу. Канал без ID ищется по имени внутри категории; если его нет и
`OPERATIONS_AUTO_CREATE_CHANNELS=true`, бот создаёт его с запретом обычных сообщений для роли
`@everyone`. Права категории копируются, поэтому закрытая административная категория остаётся
закрытой.

ID найденных или созданных каналов сохраняются в SQLite. Их можно позже закрепить в `.env`:

```env
OPERATIONS_CATEGORY_ID=1526605447878934589
OPERATIONS_AUTO_CREATE_CHANNELS=true
CONTROL_PANEL_CHANNEL_ID=0
ACTIVE_TASKS_CHANNEL_ID=1526606213826220198
WORKSHOP_CHANNEL_ID=1526606361369116672
FINANCE_EVENT_LOG_CHANNEL_ID=1526606262035550369
TECH_LOG_CHANNEL_ID=0
REPORTS_CHANNEL_ID=0
BOT_SETTINGS_CHANNEL_ID=0
BOT_TEST_CHANNEL_ID=0
```

Значение `0` разрешает автоматический поиск или создание. Для существующих активных задач,
мастерской и финансового лога заданы известные ID.

Для автоматической подготовки боту нужны `Manage Channels`, `View Channel`, `Send Messages`,
`Manage Messages`, `Read Message History`, `Embed Links` и `Use Application Commands`. Без
`Manage Channels` существующие отсеки продолжат работать, но недостающие не будут созданы; причина
появится в техническом или контейнерном логе.

## Обновление со старой схемы

При первом запуске после обновления бот:

1. создаёт или находит служебные каналы;
2. восстанавливает постоянные панели;
3. переносит активные карточки крафта в мастерскую вместе с новыми ветками;
4. переносит открытую вечернюю сверку в финансовый лог;
5. удаляет старые сообщения T-Mod из `активные-задачи`, оставляя одну живую сводку.

Данные SQLite и журнал отменяемых действий не удаляются.

## Настройки и тестовый контур

В `настройки-бота` администратору доступны:

- приватная диагностика задержки Discord, каналов и рабочих данных;
- повторная проверка структуры;
- обновление постоянных панелей.

В `тест-бота` кнопка **«Проверить T-Mod»** выполняет только чтение. Она не создаёт финансовых
операций, крафтов, законопроектов или записей аудита. Администратору также доступна приватная
кнопка **«Проверить Majestic»**: она проверяет API для сервера `RU15` через общий кэш и не
показывает ключ.
