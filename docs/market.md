# Рыночный каталог T-Mod

## Назначение

Модуль `modules/market.py` превращает агрегированную статистику Majestic в переиспользуемый
локальный каталог. Команда Discord, будущая себестоимость крафтов и отчёты должны читать один и
тот же слой данных, а не обращаться к API независимо друг от друга.

## Поток данных

1. Один фоновый worker последовательно запрашивает `items`, `vehicles` и `clothes`
   для `RU15` раз в `MARKET_REFRESH_SECONDS`: три запроса при лимите пять в минуту.
2. Типизированный парсер проверяет envelope, количество строк и уникальные ключи.
3. `storage.market_replace_snapshot()` атомарно обновляет текущий каталог SQLite.
4. История получает запись только для нового сочетания `category + externalId + lastUpdated`.
5. Поиск `/market` читает локальную базу и не расходует лимит Majestic.

Если синхронизация завершилась ошибкой, текущие строки не деактивируются и пользователи продолжают
видеть последний хороший каталог. Ошибка и число последовательных сбоев сохраняются отдельно;
повторяющиеся уведомления в `#лог-тех` ограничены cooldown.

Когда меняется `lastUpdated` хотя бы одного каталога, бот отправляет в `#лог-тех` одно сводное
уведомление с `@everyone`. Обновившиеся предметы, автомобили и одежда объединяются в одну карточку,
поэтому один цикл не создаёт три отдельных пинга. Первая загрузка пустой базы и повторный ответ с тем
же `lastUpdated` уведомление не создают. Для реального пинга роли боту требуется право Discord
**Mention @everyone, @here, and All Roles** в техническом журнале.

## Таблицы SQLite

| Таблица | Назначение |
|---|---|
| `market_catalogs` | состояние синхронизации, сервер, период и свежесть источника |
| `market_items` | текущие предметы, автомобили и варианты одежды с `external_id` и JSON-метаданными |
| `market_item_history` | снимки цены, уникальные по `server/category/item/lastUpdated` |
| `market_alerts` | личные условия пользователей и состояние одноразового сигнала |
| `market_alert_notifications` | устойчивая очередь доставки сигналов в Discord ЛС |

Старые записи не удаляются: при исчезновении из очередного полного ответа они становятся
неактивными. Это сохраняет связь с будущими рецептами и историческими отчётами.

## Русский поиск

Индекс приводит строку к Unicode NFKC, нижнему регистру, заменяет `ё` на `е`, убирает лишнюю
пунктуацию и пробелы. Ранжирование учитывает:

* точный `#itemId`;
* model-код автомобиля;
* полное название;
* начало и вхождение строки;
* совпадение частей слов;
* небольшие опечатки через нечёткое сравнение;
* транслитерацию кириллицы для латинских марок и моделей (`пегасси` → `Pegassi`).

Сначала возвращается наиболее точное совпадение, при одинаковой точности выше поднимается предмет
с большим числом продаж.

## Публичный интерфейс

`/market` работает в любом серверном канале и всегда отвечает приватно. В меню есть переключатель
**Предметы / Автомобили / Одежда**. Необязательные параметры `category` и `query` поддерживают Discord autocomplete.
То же меню открывается кнопкой **«Рынок»** из общей и
личной панели `/tvrs`.

Карточка показывает среднюю, минимальную и максимальную цену, объём и продажи, период,
время обновления Majestic и динамику между сохранёнными срезами. Интерфейс прямо обозначает, что
это статистический ориентир, а не список live-объявлений.

## Личные рыночные сигналы

В карточке любой категории пользователь задаёт максимальную цену за штуку и минимальное количество
размещений. Один пользователь может хранить до `MARKET_MAX_ALERTS_PER_USER` сигналов; для одного
предмета создаётся только один сигнал, повторное сохранение обновляет его.

Сигнал умышленно не пересчитывается при каждом минутном запросе. `lastUpdated` Majestic определяет
версию статистического среза, и каждое условие проверяется только один раз для новой версии. Это
исключает повторные ЛС, если API много раз возвращает одинаковые данные.

Для цены используется положительный `minPrice`, а при его отсутствии — `averagePrice`. Количество
сравнивается с `totalCount`. Для одежды API не возвращает `totalCount`, поэтому условие сравнивается с `soldCount`
и в интерфейсе подписано как «продано за период». Ни одна из этих метрик не гарантирует live-остаток.
При совпадении условий создаётся запись в постоянной очереди, бот отправляет ЛС и завершает сигнал.
Пользователь может снова включить, изменить, поставить на паузу или удалить его через `/market`.

Временная ошибка Discord повторяется до `MARKET_ALERT_MAX_DELIVERY_ATTEMPTS` раз с интервалом
`MARKET_ALERT_RETRY_SECONDS`. После окончательной ошибки сигнал ставится на паузу; сырой текст
ошибки пользователю не показывается.
