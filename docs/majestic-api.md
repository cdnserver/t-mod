# Majestic API

Интеграция состоит из безопасного HTTP-клиента и локального рыночного каталога T-Mod. При
включённом API бот синхронизирует предметы RU15 по расписанию, а пользовательский поиск работает
по SQLite и не выполняет отдельный запрос для каждого человека.

## Подтверждённые параметры

По опубликованной документации Majestic:

* базовый адрес — `https://api.majestic-files.net`;
* ключ передаётся только в заголовке `x-api-key`;
* язык передаётся в `x-language`;
* показанный лимит — 5 запросов за 60 секунд;
* общие ошибки — `401 UNAUTHORIZED`, `403 NO_API_ACCESS`, `429 TOO_MANY_REQUESTS`, `500 INTERNAL_SERVER_ERROR`;
* доступны marketplace-маршруты для транспорта, предметов, домов, квартир, складов, офисов и одежды.

Публичной OpenAPI-схемы по стандартным адресам не найдено, поэтому форматы JSON-ответов намеренно не зафиксированы в моделях до получения реальных примеров или официальной схемы.

## Переменные окружения

Настройки добавляются в постоянный файл `C:\Users\Admin\Documents\SGLDiscordBot\.env` автоматически при запуске `run_windows.bat`:

```env
MAJESTIC_API_ENABLED=false
MAJESTIC_API_BASE_URL=https://api.majestic-files.net
MAJESTIC_API_KEY=
MAJESTIC_API_KEYS=
MAJESTIC_API_LANGUAGE=ru
MAJESTIC_SERVER_ID=RU15
MAJESTIC_API_REQUESTS_PER_WINDOW=5
MAJESTIC_API_WINDOW_SECONDS=60
MAJESTIC_API_TIMEOUT_SECONDS=15
MAJESTIC_API_CACHE_TTL_SECONDS=60
MAJESTIC_API_MAX_RETRIES=1
MAJESTIC_API_RETRY_BACKOFF_SECONDS=1
MARKET_REFRESH_SECONDS=60
MARKET_HISTORY_RETENTION_DAYS=400
MARKET_EMBED_COLOR=0xD9D9D9
```

Настоящий ключ нельзя добавлять в GitHub, `.env.example`, сообщения Discord или логи. Он хранится только в постоянном `.env` домашнего сервера.

## Что уже делает клиент

Файл `modules/majestic_api.py` предоставляет:

* обязательные заголовки авторизации и языка;
* общий скользящий лимит запросов в единственном клиенте приложения;
* TTL-кэш одинаковых GET-запросов;
* безопасную диагностику без значений ключей;
* понятные исключения для `401`, `403`, `429`, `500` и сетевых ошибок;
* чтение `Retry-After` при ответе `429`;
* короткие повторы только для сетевых ошибок и `5xx`;
* синхронный и асинхронный интерфейс;
* показанные в документации marketplace-маршруты;
* буквенно-цифровые ID серверов Majestic, включая зафиксированный для проекта `RU15`.

## Проверенный ответ RU15

15 июля 2026 года тестовый запрос `marketplace/items/RU15` успешно вернул сервер
`RU15 · Phoenix`, статистику за 30 дней и 1315 товарных позиций. Для каждого предмета доступны
`itemId`, название, количество размещений и продаж, средняя, минимальная и максимальная цена.

В `#тест-бота` добавлена приватная администраторская кнопка **«Проверить Majestic»**. Она читает
общую статистику предметов, показывает состояние подключения и использует общий TTL-кэш клиента.
Ключ в Discord и логах не отображается.

Команда `/market` и кнопка **«Рынок»** в панели Товарищества доступны всем участникам. Они ищут
русские названия, части слов, небольшие опечатки и `#itemId`, показывают подробную карточку и
никогда не публикуют результат в общий канал.

Из карточки можно создать личный сигнал по максимальной цене и минимальному количеству. Он
проверяется только при смене `lastUpdated`, сохраняется в SQLite и доставляется в ЛС через
устойчивую очередь. Повтор одинакового среза не создаёт повторное уведомление.

Пример будущего вызова из асинхронного обработчика:

```python
from modules.majestic_api import get_majestic_api_client

client = get_majestic_api_client()
items = await client.marketplace_async("items")  # использует MAJESTIC_SERVER_ID=RU15
```

Все будущие функции бота должны получать клиент через `get_majestic_api_client()`. Так они используют один кэш и один общий бюджет, а не создают отдельный лимитер для каждой команды.

## Несколько API-ключей

Каркас умеет безопасно прочитать несколько ключей и показать их количество в диагностике, но сейчас выполняет запросы только основным `MAJESTIC_API_KEY`. Общий лимит остаётся 5 запросов за 60 секунд.

Несколько ключей дадут 15–20 запросов в минуту только при одновременном выполнении двух условий:

1. Majestic считает квоту отдельно для каждого ключа, а не для аккаунта, владельца приложения или IP-адреса.
2. Правила Majestic прямо разрешают объединять ключи одного приложения для увеличения общей частоты.

В текущей документации этого подтверждения нет. Автоматическая смена ключа после `429` выглядела бы как обход ограничения и может привести к блокировке всех ключей. Поэтому она намеренно не реализована.

Перед расширением лимита нужно получить у Majestic письменный ответ на вопрос:

> Лимит 5 запросов за 60 секунд применяется к одному API-ключу, аккаунту/владельцу или IP? Разрешено ли одному приложению распределять запросы между несколькими своими ключами для суммарной частоты 15–20 запросов в минуту?

Если Majestic разрешит объединение, режим пула можно будет добавить отдельно, сохранив общий контролируемый бюджет и обработку `429`.
